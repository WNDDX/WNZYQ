# 平台设置 · 优化方案

> 这份方案的每一条都基于 2026-11-04 的实测（线上 v529）与代码结构，不是凭感觉写的。
> 文中「实测」= 有断言数据；「建议」= 我的判断，需要你拍板。

## 一、先给结论：平台设置现在能用吗

**能正常打开和关闭的（实测 7/7）**：

| 入口 | 打开 | 右上角 × 关闭 | 「关闭」键 | 备注 |
|---|---|---|---|---|
| 设置信息 | ✓ | ✓ | — | 三类客服行（咨询/群聊/公众号） |
| 设置公告 | ✓ | ✓ | ✓ | 富文本能真实输入并加粗（实测 `<b>这个是真实输入的文字</b>`） |
| 批量导入 | ✓ | ✓ | — | 模板能生成，实测 34,541 字节的 xlsx |
| 数据缓存 | ✓ | ✓ | — | 实测 18 行历史数据 |
| 系统体检 | ✓ | ✓ | — | 弹窗正常 |
| 账号管理 | ✓ | ✓ | ✓ | 可反复打开；下拉已接管、权限 6 组成行、勾选对齐、底部两键 |
| 修改密码 | ✓ | ✓ | ✓ | 3 个输入框 + 两键 |
| 资源采集 | ✓ | ✓ | — | 上架/删除确认在 v524 实测通过；采集真跑在 v501~v503 实测（57 个真实商城里 20 个可抓） |

**关掉之后不会留遮挡**：7 个弹窗点 × 后 `masks=[]`、页面滚动锁恢复 `hidden scroll`，可以立刻点下一个功能。这条我专门测了，因为遮罩残留会让人以为"页面卡死"。

**所以「能不能用」这一层是过关的。** 下面说的是"用起来顺不顺、像不像一套成熟系统"。

## 二、需要优化的（按优先级，每条都给改法）

### P0 · 直接影响使用

**1. 设置页太长，八件事平铺到底**
- 现状：8 个入口分 4 组竖排，实测「账号管理」按钮在 y=896（视口高 900），几乎贴着屏幕底边才出现；「修改密码」更低。
- 改法：页面顶部加**横向锚点条**（基本设置 / 采集导入 / 账号安全 / 系统维护），点一下滚到对应组；组标题做成可折叠，默认只展开第一组。
- 好处：不用滚三屏找按钮。

**2. 资源采集弹窗信息密度过高**
- 现状：一个弹窗里塞了「平台下拉 + 3 个动作键 + 3 个页签 + 搜索 + 状态筛选 + 计数 + 批量条 + 卡片网格 + 分页 + 提示条」，手机上一屏只看到 2 张卡。
- 改法：把「采集」和「资源池」拆成两个入口（或两个页签分两屏），采集页只留"选平台 + 采集/粘贴 + 结果"，资源池页只留"搜索 + 筛选 + 卡片 + 分页"。
- 好处：每屏只做一件事，手机上不再挤。

**3. 采集时 20 秒黑等，没有进度**
- 现状：点采集后按钮变「采集中…」，提示「最多 20 秒」，但用户不知道进行到哪一步。
- 改法：分三段反馈——「正在连对方平台」→「已拿到 N 条，正在补详情 (3/8)」→「入库完成」。后端已经有 `found/added` 数据，加阶段字段即可。
- 好处：等待可预期，不会以为卡死。

**4. 批量导入没有"上次导入结果"**
- 现状：导入完只弹一次 toast，关掉就没了；下次想核对"上次导了几条、哪条失败了"无从查。
- 改法：弹窗里加「导入历史」小列表（时间 / 文件 / 成功条数 / 失败原因），保留最近 10 次。
- 好处：出问题能回溯。

**5. 数据缓存（回收站）没有搜索**
- 现状：18 行还能翻，时间一长就是几百行滚到底。
- 改法：复用资源列表的搜索框组件，按标题/类型筛。

**6. 账号权限没有"角色模板"**
- 现状：6 组权限、二十多个勾选框，每加一个子账号都要从头点一遍。
- 改法：表单顶部加三个预设：**只看数据**、**只管资源**、**只管采集**，点一下自动勾好，再微调。
- 好处：加人从两分钟变十秒。

### P1 · 一致性

**7. 八个入口都是同款 46px 蓝实心大键，排成一堵"按钮墙"**
- 改法：一组里只保留 1 个主操作（蓝实心），其余降为行内键（白底描边）。例如「基本设置」里只有「设置信息」是主键，「设置公告」降级。

**8. 弹窗内容模板不统一**
- 现状：设置信息是"可折叠行"、账号是"表单 + 权限网格"、公告是"编辑器 + 列表"、体检是"控制台风格深色块"。
- 改法：定两种模板——**表单型**（标题 + 字段 + 底部两键）和**列表型**（标题 + 工具行 + 列表 + 分页）。体检的深色控制台改成白卡 + 结果分组，跟其它弹窗一致。

**9. 修改密码没有强度提示**
- 改法：输入时实时显示「弱 / 中 / 强」和一句建议（长度、字母数字混合）。

### P2 · 锦上添花

**10. 设置信息的三类客服没有"测一下"**
- 现状：填了链接不知道对不对，只能前台点一次试。
- 改法：每行加「测试打开」小键，点了新窗口打开该链接。

**11. 公告列表没有预览**
- 改法：每行加「预览」，用前台公告弹窗的样式渲染（复用 `/shop` 的公告组件，不另画）。

**12. 系统体检结果不能定位**
- 现状：列出"哪张图失效"，但要自己去资源管理里找。
- 改法：每行加「去处理」，直接跳到对应资源并打开编辑窗。

## 三、建议去除 / 合并的

| 项 | 现状 | 建议 | 理由 |
|---|---|---|---|
| 「采集记录」页签 | 第三个页签，记录每次采集成败 | **合并到「我的平台」每行下方**，用一行小字显示"上次采集：3 小时前，抓到 19 条" | 单独一页信息量太少，且与平台强相关 |
| 批量导入的「选项」工作表 | 模板里第 5 张表，只有下拉源数据 | **设为隐藏工作表**（Excel 支持隐藏，下拉照常可用） | 用户看到会疑惑"这表要填吗" |
| 系统体检的"深色控制台" | 黑底绿字，像开发者工具 | 改成白卡 + 红/黄/绿三色分组 | 跟全站风格不一致，且老板说"看着吓人" |
| 「数据缓存」这个名字 | 实际是回收站（删掉的资源/分类/公告） | 建议改名「回收站」 | 名字和功能对不上；但这是你之前定的名字，**要你点头才改** |

## 四、建议增加的功能（按价值排序）

1. **定时采集**：每个平台可设"每天 9 点自动采一次"，采到新资源进池并标"新"。
   - 价值最高：现在是手动点，容易忘。
   - 成本：需要定时任务（Cloudflare Cron），约 1 天。
2. **采集去重规则可视化**：现在按"同平台 + 同标题"去重，用户看不到规则，也不知道为什么某条没进来。加一个"本次跳过 N 条（标题重复）"的明细。
3. **上架前批量改分类**：批量选中后可以一次归到某个分类，不用逐条改。
4. **账号操作日志**：谁在什么时候改了设置/删了资源，保留 30 天。多人共用平台时必需。
5. **设置项导出/备份**：把平台清单、客服信息、公告导出成一个文件，换环境能导入。
6. **平台健康度**：每个平台显示"最近一次成功采集时间 + 条数 + 失败原因"，一眼看出哪个平台挂了。
7. **采集失败一键转粘贴**：失败提示旁边直接给「改用粘贴」按钮，不用退出去重找。

## 五、落地顺序（建议分三批，每批一次上线）

**批次 1（体验痛点，约 1 天）**
- 设置页锚点导航 + 分组折叠
- 采集进度三段提示
- 回收站搜索
- 密码强度提示

**批次 2（一致性 + 效率，约 1 天）**
- 按钮分级（主/次）
- 体检结果改白卡分组
- 账号角色模板
- 导入历史

**批次 3（能力扩展，约 2 天）**
- 定时采集
- 操作日志
- 配置导出
- 平台健康度

## 附：本轮实测中我排除掉的三个"假问题"

测试第一轮报了 3 条失败，查完都是**测试脚本自身缺陷**，不是系统问题，记录在此避免以后重复怀疑：

1. 「账号管理打不开」→ 按钮在 y=896（视口 900），脚本没滚动就点，点到了屏幕外。修法是点击前 `scrollIntoView`。
2. 「公告编辑器打不进去字」→ 脚本用逐字符键盘事件发中文，CDP 对非 ASCII 不触发输入。改用 `Input.insertText`（等价输入法上屏）后正常。
3. 「密码弹窗关不掉」→ 脚本连点太快，上一步的关闭动画还没结束。单独测 7 个弹窗点 ×，全部 `masks=[]`、`display:none`，关闭是干净的。
