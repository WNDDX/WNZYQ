# 「外部平台链接采集 + 一键跳转」设计方案（待老板定夺）

> 版本 v1 · 2026-11-02 · 只做设计，未写代码。你点头我再动手。

## 一、你要解决的问题

你现在的流程是：想挂某个外部平台（某宝/某鱼/某站）的产品 → 打开那个平台 → 找产品 → 复制链接 → 回后台 → 粘贴进资源。中间"找链接"这一段全靠人肉。

目标：**在后台里就能把外部产品"取"进来，以后点一下就跳回去看。**

## 二、核心设计：一张"外部商品"表 + 一套"采集卡"

### 1. 数据结构（新增 1 张表，不动现有表）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| platform | 平台标识（自由填，如 某宝 / 某鱼 / 官网） |
| title | 商品标题 |
| price | 价格（可空） |
| url | 商品链接（必填，唯一索引） |
| img | 封面图（可空） |
| note | 你自己的备注（进价、利润、能不能做） |
| cid | 归到哪个分类（可选，方便和站内资源对齐） |
| status | 在用 / 已下架 |
| created_by | 谁加的（沿用现有子账号体系） |
| created_at / updated_at | 时间 |

### 2. 三种"进来"的方式（按成本从低到高）

**方式 A · 手动登记（先做这个，最稳）**
后台新增一个「外部商品」页签：填标题 + 链接 + 备注，可选分类。列表可搜索、可批量导（复用现有 Excel 导入通道，加一个「外部商品」工作表）。

**方式 B · 一键抓取（在 A 之上加）**
粘贴链接 → 点「抓取」→ 服务端去读该页面，尽量取回标题 / 价格 / 主图 / 简介。
- 限制要说清：**很多平台有反爬**（需要登录、有风控、返回 JS 壳），能抓到什么平台就抓什么，抓不到就退回手动填。
- 技术上：一个小接口 + 白名单域名，失败就返回"这个平台抓不到，请手填"，不报错卡住。

**方式 C · 浏览器书签小工具（中期做，最省事）**
做一个书签按钮：你在外部平台商品页点一下，就把当前页 URL + 标题 + 首图发到我站后台。
- 优点：不受反爬限制（是你自己的浏览器在访问），成功率最高。
- 代价：需要你（或员工）在浏览器里装一个书签，我要写一小段脚本 + 一个接收接口。

> 我的建议：**先 A 落地（一天内可用），B 作为增强，C 如果常用再上**。

### 3. 怎么"用"（跳转体验）

- 后台「外部商品」列表每行一个「打开」键 → 新标签直接跳到那个平台商品页。
- 前台资源页可以选：某条资源绑定一个外部商品 → 客户点「咨询/购买」时跳到你的外部链接（和现在的客服跳转同一套机制，不新造轮子）。
- 手机上「打开」= 唤起对应 App（系统自己会做，我不需要特殊处理）。

## 三、和现有体系的联动（你要求"该同步的要同步"）

| 现有模块 | 需要同步的改动 |
|---|---|
| 权限 | 新增一组 `external.view / add / edit / del / grab`；范围锁沿用分类范围；子账号只看自己加的（`codeScope` 同思路） |
| 批量导入 | 模板加一张「外部商品」表：平台 / 标题 / 链接 / 价格 / 分类 / 备注 / 状态 |
| 信息中心 | 新增事件类型「采集外部商品」，进动态流 |
| 回收站 | 删外部商品也进缓存 60 天，可恢复 |
| 统计 | 外部商品"跳转次数"计入 stats（type=ext_click），能看哪个商品最常被点 |

## 四、要你拍板的 4 个点

1. 先做哪个：**只做 A** / **A+B** / **A+B+C**？
2. 抓取方式 B 如果某些平台抓不到，是否接受"降级为手动填"（不报错）？
3. 书签小工具 C 需要你在浏览器装一个书签，接受吗？
4. 外部商品要不要**在前台展示**（客户能点）？还是只在后台自己用？

## 五、工作量与风险（我按真实情况说）

- A：改动集中在 1 张表 + 1 个页签 + 1 个接口，风险低，不影响现有页面。
- B：要多写抓取接口，**成功率取决于平台**，我不会承诺"什么都能抓"。
- C：需要你配合装书签，且要处理跨域，工作量中等。
