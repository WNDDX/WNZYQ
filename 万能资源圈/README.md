# 万能资源圈 · 商品小店（GitHub + Cloudflare 免费版）

一个纯前端 + Cloudflare 免费云服务的虚拟商品展示小店，包含**前台商品页**和**管理后台**。

- **前台（shop.html）**：顾客看到的商品列表页，风格与你主页面的蓝白渐变一致（圆 logo、弹窗、按钮、配色相关），支持搜索、分类、详情弹窗、一键下单跳转。
- **后台（admin.html）**：你用来管理的地方——上下架商品、编辑商品描述、增删商品、管理分类、查看浏览/下单数据、修改密码。**不用改代码、不用重新部署，网页点几下就能上下架。**

> 部署成本：0 元。GitHub 仓库免费 + Cloudflare Pages（静态托管，免费）+ Cloudflare D1（数据库，5GB 免费额度）+ Pages Functions（后端接口，每天 10 万次免费请求）。无需购买服务器、无需域名。

## 三、部署到 Cloudflare（核心步骤，约 15 分钟）

整体链路：**你把代码推到 GitHub → Cloudflare Pages 自动部署网站 + 接口 → 创建 D1 数据库存数据**。

### 第 1 步：创建 GitHub 仓库并上传代码

1. 登录 [github.com](https://github.com)，点右上角 **+ → New repository**。
2. 仓库名随意（比如 `wnzyq-shop`），选 **Private（私有）**，不要勾选任何初始化文件，点 **Create repository**。
3. 把本文件夹里的这些文件和目录**原样上传**到仓库根目录（不要嵌套子文件夹）：
   - `shop.html`、`admin.html`、`config.js`、`schema.sql`、`package.json`、`wrangler.toml`、`functions/`（整个目录）
   - 上传方式：仓库首页点 **Add file → Upload files**，把这些文件拖进去，写个提交说明，点 **Commit changes**。

### 第 2 步：连接 Cloudflare Pages

1. 注册/登录 [dash.cloudflare.com](https://dash.cloudflare.com)（免费）。
2. 左侧菜单 → **Workers & Pages** → **Create** → **Pages** → 选 **Connect to Git**。
3. 按提示授权 GitHub，选中刚才的仓库，点 **Begin setup**。
4. 构建配置不用改（保持默认即可，本项目的构建命令为空、输出目录为根目录），直接点 **Save and Deploy**。
5. 等一两分钟，部署完成。Cloudflare 会给你一个 `https://xxxx.pages.dev` 的网址。

### 第 3 步：创建并绑定 D1 数据库

1. 左侧菜单 → **Workers & Pages** → 进入刚才的 Pages 项目。
2. 顶部标签切到 **Settings**（设置）→ 左侧 **Bindings**（绑定）。
3. 找到 **D1 Database**，点 **Add**：
   - 变量名（Variable name）填：`DB`
   - 数据库：选 **Create new database**，名字随便填（如 `wnzyq-shop-db`），点 Create。
4. 保存后，重新部署一次让绑定生效：**Deployments** 标签 → 找到最新一条 → 右上角 **... → Retry deployment**（重新部署）。
   - 没有 `Retry deployment` 就点 **Create deployment** 再选仓库重新部署一次。

> 说明：绑定 `DB` 变量后，后端代码就能自动读写这个数据库了。`wrangler.toml` 里的 `database_id` 可以不用管（面板绑定优先），保留文件只是备用。

### 第 4 步：初始化系统（关键）

1. 打开你的网站地址：`https://xxxx.pages.dev/admin.html`
2. 登录页底部有一个 **「初始化系统」** 按钮，点它。
   - 系统会自动建表、写入默认分类和 6 个示例商品、创建默认管理员。
3. 完成后回到登录页，用默认账号登录：
   - **用户名：admin**
   - **密码：123456**
4. 登录后**立即在右上角「改密码」换成自己的密码**（重要）。

### 第 5 步：把前台链接替换到你的主页

- 你的引导页（主页）里「获取资源」按钮跳转的链接，改成你的前台地址：`https://xxxx.pages.dev/shop.html`
- 如果想让店铺更正式，可以之后在 Cloudflare Pages 的 **Custom domains** 里绑定你自己的域名（可选）。

## 四、日常使用

### 1. 管理商品（后台 admin.html）

- **上下架**：商品列表每行有个开关，绿色=上架中、灰色=已下架，点一下就切换。前台**立刻生效**，不用改代码、不用重新部署。
- **新增商品**：点「+ 新增商品」，填标题、分类、简介、详细描述（支持换行）、图片 URL、下单链接。
- **编辑/删除**：每行有「编辑」「删除」按钮。
- **排序**：新增时填「排序值」，越小越靠前。

### 2. 管理分类（后台「分类管理」标签）

- 可新增、改名、删除分类。
- 「全部」这个分类是固定的，不能删。

### 3. 查看数据（后台「数据统计」标签）

- 顶部四个卡片：商品总数、在售中、总浏览、点击下单。
- 下方按商品明细：每个商品被浏览多少次、被点了多少次下单。
- 数据来自前台自动埋点（顾客打开商品详情=1 次浏览，点「立即下单」=1 次下单）。

### 4. 前台（shop.html）说明

- 顶部：店铺名 + 搜索框（输入即实时筛选）。
- 分类栏：横向滑动，第一个「全部」。
- 商品卡片：图 + 标题 + 简介，点卡片弹出详情（大图 + 详细描述）。
- 详情弹窗底部：**立即下单**（新窗口跳转到该商品的购买链接）+ **关闭**。
- 下架商品：前台不显示，后台数据还在。

## 五、商品图片怎么办（重要）

**推荐方式：把图片放进仓库的 `assets/images/` 文件夹，随代码一起部署。**

1. 把你的图片命名好（如 `1.jpg`、`logo.png`）放进 `assets/images/` 文件夹
2. 随整个项目一起上传 GitHub、部署到 Cloudflare Pages
3. 图片网址就填相对路径：`assets/images/1.jpg`
   - 部署后实际地址 = `https://你的域名.pages.dev/assets/images/1.jpg`
   - 前台、后台都已支持这种写法
4. 好处：永久免费、稳定不失效、同域加载快、不会被图床防盗链

**备选方式：免费图床或外链图片**
- 商品图片也可以直接填**公网 http/https 图片地址**（任何网站图片都行）
- 没有正式图片时，可用占位图：`https://picsum.photos/seed/任意英文/600/400`

**图片建议**
- 压缩到 200KB 以内、宽度 600px 左右即可，太大影响加载
- 文件名用英文或数字，避免中文/空格

## 六、常见问题

**Q：前台显示的还是示例商品，我在后台加的商品不显示？**
A：确认部署是否生效（重新部署过、D1 绑定成功、系统已初始化）。前台会在打开时请求云端数据，成功后自动显示真实商品。可以先在后台把某个商品下架，刷新前台看它是否消失来验证链路通没通。

**Q：如何把店铺名/logo 改掉？**
A：店名在后台没有可视化入口，直接改 `config.js` 里的 `shopName`（本地预览用）即可；部署后如果想彻底改，前台优先读云端……店名是从 `config.js` 渲染的，改完重新部署。也可以后续在后台加设置功能（可选）。

**Q：想彻底不用 config.js？**
A：可以，前台在连不上后端时才用它兜底，属正常设计。你完全可以把数据都维护在后台，config.js 只在本地预览时起作用。

**Q：部署出错/白屏？**
A：多数是 D1 没绑定或没初始化。检查：① Settings→Bindings 里有没有名为 `DB` 的 D1 绑定；② 重新部署过；③ 打开 `/admin.html` 点过「初始化系统」。
