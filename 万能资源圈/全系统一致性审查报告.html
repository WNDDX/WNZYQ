零、先说人话：这系统现在最大的问题是什么不用懂技术也能看懂

这套系统功能已经很全，但它是“一点点长出来的”，所以出现了三种典型的“不像一套系统”的痕迹：

  • 同一件事有两种做法。比如都是翻页：资源管理自己有一根好看的翻页条（带“跳转”），采集弹窗却自己画了“上一页/下一页”两根小按钮；都是下拉：大部分是系统的圆角下拉，个别弹窗还是浏览器自带的长条下拉。
  • 同一件事有两种叫法。删除有“删 / 删除 / 彻底删除”三种写法；数量有“个 / 件 / 条”三种单位；页面标题有“改资源 / 看资源 / 编辑资源”。
  • 同一件事有两种手感。有的三角点下去是慢慢转的，有的一下就跳；有的弹窗点空白处能关，有的不能。
这三类问题本身都不影响功能，但叠在一起，客户一眼就能看出“这不是一家做的”。下面 68 条，就是把这三类问题挖到底。

二、视觉统一性颜色 / 字号 / 间距 / 圆角 / 阴影 / 图标 / 控件

1高 同一个“删除”有四种长相
在哪：资源列表行、采集卡片、回收站、批量条。
现在：有的是白底红字小按钮，有的是蓝底按钮配红字（还带内联颜色），有的是纯文字链接。
建议：只留两种——行内小动作统一白底红字（row-btn danger），弹窗底部统一淡红（modal-close）；禁止再写内联颜色。
为什么：删除是危险动作，长相必须一致，用户才敢点。
2高 按钮有三种高度
在哪：页面里 46px、工具行 36px、行内 28px 混用，个别地方还有 34px。
现在：“采集”按钮 36px 旁边配 46px 的按钮，看着一高一矮。
建议：固定三档：主操作 46、工具行 36、行内 28。工具行里不允许出现 46。
为什么：高度不统一，眼睛会觉得“这两个按钮不是一套的”。
3中 圆角有三套：8 / 10 / 12
现在：大部分 10px，行内小按钮 8px，弹窗 12px。
建议：写进规范并标注用途，禁止出现 6px、14px 这种“凭手感”的值。
为什么：圆角是“同一套系统”最直观的信号。
4中 字色深浅不统一
现在：说明文字有 #666、#888、#999、#8aa0b5 四种灰。
建议：收敛成三档：主文字、次要文字、提示文字；其余全删。
为什么：灰色太多，页面看起来“脏”。
5低 图标风格混用
现在：一部分是线性图标，一部分是实心三角，个别是 emoji（📭）。
建议：统一线性、统一 2px 线宽；emoji 全部换成图标。
为什么：emoji 在不同手机上长得不一样，客户截图会显得很业余。
6中 卡片阴影深浅不一
现在：有的卡片有阴影、有的只有描边；弹窗阴影有两个版本。
建议：卡片一律“细描边 + 极轻阴影”，弹窗一律一档大阴影。
7中 深色模式下少数控件没跟上
现在：大部分已适配，但个别自造控件（采集卡片、权限树）在深色下边框偏亮。
建议：自造控件一律用颜色变量，不要写死颜色。
8低 列表行高不统一
现在：资源行约 64px，采集卡片里的行更矮，信息中心又是另一种。
建议：同类列表统一行高与内边距。
9低 选中态样式两套
现在：资源列表选中是“整行淡蓝”，采集卡片选中是“蓝框 + 右上勾”。
建议：列表用整行淡蓝，卡片用蓝框，但要写进规范（卡片没有“行”的概念，允许不同）。
10中 弹窗标题字号不一致
现在：大部分 20px 居中，个别自造弹窗是 18px 左对齐。
建议：全部 20px 居中，副标题用 13px 灰字放标题下方。
11低 输入框高度不统一
现在：表单里 44px，搜索框 34~36px 来回改。
建议：表单 44、工具行 36，写死两档。
12低 “危险区”没有统一的视觉语言
建议：凡是不可恢复的操作（删除、清空、彻底清除），统一用红字 + 二次确认；可恢复的（进回收站）用普通样式。

三、组件规范弹窗 / 表格 / 表单 / 提示 / 加载 / 空状态

13高 下拉框还有“原生态”漏网
在哪：账号编辑里的“上级账号”、批量导入预览里的部分选择。
现在：大多数是系统圆角下拉，这几个还是浏览器自带的长条。
建议：弹窗一生成就补一次“下拉升级”（本轮已加统一入口，后续新弹窗必须调用）。
为什么：这是最容易被一眼看穿的“不是一套”。
14高 翻页组件两套
现在：资源管理/统计是公共翻页（上一页 + 页码 + 跳转），采集弹窗原来是自己画的。
建议：已改为公共组件；以后任何列表都只准用它。
15中 空状态有三种写法
现在：①图标+标题+说明（标准）②一行灰字 ③干脆空白。
建议：统一走标准空状态，并区分“真没有”和“筛没了”两句话。
16中 加载状态不统一
现在：有的地方骨架屏，有的地方转圈，有的地方“正在读取…”文字。
建议：列表用骨架屏、弹窗用一行“正在读取…”，按钮用转圈 + 文案变“保存中…”。
17高 提示条（Toast）位置不统一
现在：大多在顶部居中，个别自造提示在右下角。
建议：全部用同一个提示条，顶部居中、3 秒消失。
18高 二次确认框有两种
现在：一种是系统确认框（有标题、正文、两个按钮），个别地方直接用浏览器自带的弹窗。
建议：禁止使用浏览器自带弹窗（丑、且手机上像病毒）；一律用系统确认框。
19中 表格样式两套
现在：数据统计用的表格和资源列表是两种：一个纯表格，一个卡片式。
建议：保留两种形态（数据看表、资源看卡），但表头、行高、斑马纹、空行提示要一套。
20中 表单里“必填”的标记不统一
现在：有的写“（必填）”，有的写红星，有的什么都不写。
建议：统一红星 + 提交时红框提示，不要用文字括号。
21中 弹窗底部按钮数量不一致
现在：有的 1 个（保存）、有的 2 个、有的 3 个。
建议：固定“主操作 + 关闭”两个；需要第三个动作（如预览）放左侧并弱化。
22低 弹窗宽度没有遵守五档
现在：规范里有 480/520/680/880/940 五档，个别自造弹窗还写死 560、620。
建议：全部改成五档之一。
23低 “关闭”按钮位置不统一
建议：右上角 × 永远有；底部“关闭”永远在最右；不允许只有底部没有 ×。
24低 图片占位图有两种
现在：一种是灰色方块，一种是斜纹。
建议：统一斜纹 + 中间小字“无图”。

四、交互与体验悬停 / 点击 / 动画 / 反馈

25高 三角展开的动画不统一
现在：编辑器那条有动画，分类折叠、统计折叠有的有有的没有。
建议：所有三角统一 0.18 秒缓动，且“内容高度”也要一起过渡，不是只有三角转。
为什么：有的动有的不动，用户会觉得“卡了一下”。
26高 按下没有反馈的按钮
现在：大部分按钮按下去会缩小一点，少数自造按钮完全没反应。
建议：所有可点元素统一“按下缩到 94%”，并提供禁用态（变灰 + 点不动）。
27中 保存成功的反馈不一致
现在：有的按钮变“✓ 已保存”，有的弹提示条，有的什么都不提示。
建议：按钮就地变“✓ 已保存”停 0.4 秒 + 弹窗自动关；不要再用提示条重复一遍。
28中 加载中重复点击没有保护
现在：采集、保存这类耗时操作，按钮会变“处理中”，但个别地方没锁，连点会发两次请求。
建议：统一“点一次就禁用，成功或失败再恢复”。
29高 滚轮/滑动在弹窗里的手感不一致
现在：有的弹窗滑到底会把整页带着滚，有的不会。
建议：弹窗内滑到底不外传（页面不动），这是最不容易误操作的做法。
30中 点遮罩关闭有的能有的不能
建议：普通弹窗允许点空白关闭；正在填写的表单禁止（防误触丢内容），改为“点空白弹确认”。
31中 错误提示只说“失败”，不说为什么
现在：“保存失败”“采集失败”。
建议：必须带原因和下一步，例如“对方站点拒绝了服务器（HTTP 520），换浏览器打开或粘贴”。
32低 没有统一的“撤销”
建议：删除类操作统一进回收站（保留 60 天），并在提示条上给“撤销”按钮。
33低 键盘操作缺失
建议：Esc 关弹窗、回车提交、Tab 能走完表单。这是“专业感”的细节。
34中 长任务（采集）没有进度感
现在：只说“采集中…”，十几秒里用户不知道到哪了。
建议：显示“已抓到 N 条 / 正在补第 M 条详情”。
35低 剪贴板粘贴没有明确的落点提示
建议：粘贴框获得焦点时高亮，并显示“按 Ctrl+V”的浮动提示。
36低 切页签会跳到页面顶部
建议：切页签记住各自滚动位置（部分已做，仍有遗漏）。

五、布局与响应式结构 / 栅格 / 留白 / 各端适配

37高 手机上弹窗底部按钮会被手机键盘挡住
建议：弹窗高度用“可视高度”而不是屏幕高度，键盘弹出时自动收缩。
38中 采集卡片在窄屏挤成两列，标题只剩一行
建议：窄屏改一列，或把“编辑/查看/删除”收进“⋯”菜单。
39中 筛选项换行后没有对齐
现在：搜索框、下拉、计数挤在一行，换行后高低不齐。
建议：筛选项分组：第一行搜索 + 状态，第二行计数 + 批量操作（已按此改）。
40低 页面底部留白不一致
建议：统一底部留 24px，滚动到底不贴边。
41低 表格在窄屏会横向溢出
建议：窄屏把表格转成“每行一张小卡片”的堆叠布局。
42低 深色模式下页面切换有白闪
建议：首帧就把背景色写死在页面头部，样式晚到也不会闪白。
43低 横屏（手机横过来）没专门适配
建议：横屏时弹窗改成“左右两栏”，缩短滚动距离。
44低 顶栏在窄屏挤成两行
建议：窄屏只留 logo + 三个主键，其余收进“更多”。

六、文案规范术语 / 按钮字 / 提示语 / 标点

45高 “删除”有三种写法
现在：删 / 删除 / 彻底删除。
建议：统一“删除”；不可恢复的意思写进确认框正文。
46高 数量单位三种
现在：个 / 件 / 条。
建议：统一“个”（资源），设备用“台”。
47高 “商品”与“资源”混用
现在：界面基本已统一成“资源”，但权限、提示里还有残留。
建议：全站只准出现“资源”两个字。
48中 按钮用词不统一
现在：“确定 / 保存 / 提交 / 完成”混用；“取消 / 关闭 / 返回”混用。
建议：弹窗主操作一律“保存”或“确定”，副操作一律“关闭”。
49中 提示语有的带句号有的不带
建议：短提示不带句号，长说明带句号；数字与单位之间空一格。
50中 中英文混排没加空格
现在：“HTTP520”“60天”。
建议：中英文、数字之间加空格：“HTTP 520”“60 天”。
51低 时间格式三种
现在：“11-04 10:30”“2026-11-04”“11/4”。
建议：列表用“月-日 时:分”，导出用完整年月日。
52低 专业词吓人
现在：“渠道码”“SPA 首页壳”“子账号”。
建议：换成“分享链接里那串码”“这个地址只有框架、内容要浏览器才加载”。

七、代码质量重复 / 命名 / 可维护性

53中 同一个功能写了两遍
现在：翻页、空状态、下拉、按钮图标化都各有一份“自己写的”。
建议：公共组件只留一份，谁需要谁调用；新代码禁止复制粘贴老代码。
54中 样式写死在行内
现在：还有不少 style="color:#c62828" 这种。
建议：全部改成 class；改配色时才能一处生效。
55中 5 个后台脚本靠“全局变量”互相调用
现在：A 文件里调用 B 文件里的函数，名字写错就静默失效（今晚就踩到过一次）。
建议：公共方法统一挂在 window 上并在文档里登记；调用前先判断存在。
56低 魔法数字多
建议：高度、圆角、层级这些数字收敛成变量，加一处改全站。
57低 死代码还在
现在：已经清过一轮（旧外部链接模块），但还有几个没人调的接口和样式。
建议：每季度清一次，避免“看不懂哪段有用”。
58低 版本说明堆在代码里
现在：已把 40KB 的历史注释清到 6KB，历史移进文档。
建议：以后只留“最新一条 + 指向文档”。
59低 命名中英混杂
现在：extc、pm、uf、rc 这种缩写只有原作者懂。
建议：新代码用完整单词，老代码加注释说明。
60低 没有自动化检查
建议：上线前跑一次“语法检查 + 关键页面截图”，这次就是这么抓出一堆问题的。

八、性能与可访问性快不快 / 能不能被所有人用

61中 采集一次要 5~20 秒
建议：先入库列表（1 秒内出结果），详情放后台慢慢补，页面显示进度。
62中 后台一次要下载 5 个脚本
建议：合并压缩，或按页签懒加载（打开哪个页签才下哪个）。
63低 列表一次性渲染太多卡片
建议：超过 100 条用“滚动到底再加载”。
64中 键盘 Tab 走不完表单
建议：视觉上隐藏的按钮不要拦 Tab；弹窗打开时焦点落到第一个输入框。
65中 只有图标的按钮没有文字说明
建议：给每个纯图标按钮加“读屏名字”（aria-label），手机长按也能看到说明。
66低 文字对比度偏低
现在：浅灰提示文字在白底上有点糊。
建议：提示文字至少调到能看清的灰度。
67低 动效没有“减弱动画”开关
建议：系统设置里开了“减少动态效果”的用户，自动关掉过渡。
68低 图片没有替代文字
建议：封面图、详情图补 alt；加载失败要有占位，不要裂图。

九、你直接问的四个问题一次说明白

1）“下单链接自动带进跳转链接”——到底是哪个框？

是「新增资源」弹窗里、资源价格下面那个「跳转链接」输入框（以前叫“专属客服链接”）。它的作用是：访客在你站里点“获取资源/咨询”时，跳到对方平台这件商品的页面去下单。采集来的“下单链接”就自动填在这里，你不用手抄。

2）导入模板里那张「选项」工作表是干什么的？

它不是给人填的，是给 Excel 的“下拉菜单”当选项来源的。模板里有三列下拉（所属分类、分类级别、显示状态），Excel 需要一张表存这些选项，所以单独放了一张「选项」表。你不用管它，也不要删，删了下拉箭头就点不开了。

3）为什么点了“上架”却没真上架，还显示“已上架”？

因为老代码在“打开新增资源”那一刻就把采集记录标成了已上架，你后面取消，它也不会改回来。现在改成“新增资源保存成功”之后才标；取消就还是“未上架”。

4）预览效果和前台不一样？

「预览效果」用的是预览专用的样式，跟前台资源页确实有差异（图片按比例、价格位置、按钮样式）。建议下一步把预览直接改成“拿前台的样式来渲染”，做到“改一个字，预览立刻变”，这才叫真预览。这条我列为下一步第一优先。
